# PDF Merger & Splitter — en-US Play Store Listing

## Purpose

Create a clear, conversion-focused Play Store listing for a practical PDF organization utility.

The listing should communicate that users can:

* Merge several PDF files into one organized document
* Control the order before merging
* Split one PDF using several page-based methods
* Review page ranges before creating the results
* Choose or adjust a result cover page when supported
* Save, open, and share the PDF files they create
* Process document content directly on their device

The app should not be positioned as a full PDF editor, PDF reader, document scanner, OCR tool, compressor, format converter, repair tool, password-removal utility, cloud service, electronic-signature tool, or AI document processor.

## Long Description

Merge multiple PDF files into one organized document or split a long PDF into new files using the method that works best for you.

With PDF Merger & Splitter, you control how documents are arranged and how the resulting PDF files are created.

Select several PDFs, place them in the order you want, review the planned result, and create one new document containing all of them.

You can also select one PDF and divide it in several ways:

* Split using existing bookmarks when available
* Choose the pages where each new PDF should begin
* Divide the document into a selected number of balanced page groups
* Set custom split points
* Split using a maximum number of pages per file

Review the page ranges and filenames before creating the results.

## Notes / Assumptions

* “Maximum pages” refers to the number of pages in each result, not a maximum file size in bytes or megabytes.
* “Selected number of balanced parts” is safer than promising files of exactly equal size.
* Bookmark-based splitting depends on bookmarks already available in the source PDF.
* “Open” means opening the result with a compatible installed application.
* The app should not imply that it reads or edits PDFs internally.
* Source PDFs and generated results must remain visually distinguishable.
* Do not claim unlimited inputs unless practical Android memory and processing behavior have been validated.
* Example documents must be fictional, authorized, or created specifically for the assets.
* Do not show real names, addresses, signatures, account numbers, identification numbers, QR codes, or barcodes.
* Do not imply scanning, OCR, compression, repair, password removal, format conversion, electronic signing, or cloud processing.
* Do not promise that digital signatures remain valid after PDF rewriting.
* Do not promise perfect preservation of interactive forms, complex bookmarks, page labels, internal destinations, annotations, embedded files, or advanced PDF actions.
* The optional cover-page workflow should remain secondary to document and page organization.
* “Processed on your device,” “No account,” and “No document uploads” are supporting trust messages, not the main product promise.
* Do not claim complete offline operation if rewarded ads, purchases, or entitlement checks require an internet connection.
