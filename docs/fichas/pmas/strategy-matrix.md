# PDF Merge & Split — Strategy Matrix

## Purpose

Definir la estrategia regional de conversión para PDF Merge & Split en todos los locales compatibles de Play Store.

Esta matriz guía:

* fichas localizadas de Play Store
* nombres y descripciones ASO
* feature graphics
* orden y cantidad de screenshots
* dirección visual
* selección de paletas
* ejemplos regionales de documentos
* conversion audits
* generación masiva de assets
* QA de promesas técnicas

La verdad del producto debe mantenerse en todos los locales:

**PDF Merge & Split permite unir varios PDF en un solo documento o dividir un PDF en archivos nuevos usando marcadores disponibles, puntos de división elegidos, partes equilibradas por páginas o un máximo de páginas por archivo.**

La aplicación también permite, como parte del flujo:

* ordenar los PDF antes de unirlos
* revisar cómo quedarán distribuidas las páginas
* añadir o ajustar una portada o primera página cuando el flujo lo permita
* guardar los PDF creados
* abrirlos con aplicaciones compatibles
* compartirlos
* encontrarlos nuevamente en My PDFs
* procesar el contenido localmente en el dispositivo
* cambiar idioma y tema
* quitar anuncios mediante una opción de mejora

La estrategia regional debe adaptar la prioridad, el tono, los ejemplos y la narrativa según lo que más favorezca la conversión en cada mercado.

No debe limitarse a traducir una ficha global ni presentar PMAS como EMAS con un formato distinto.

---

# Global Strategy

El recorrido global recomendado es:

**elegir unir o dividir → ordenar documentos o páginas → revisar los rangos → preparar el resultado → crear nuevos PDF → mantener el control local**

La aplicación debe percibirse como una herramienta especializada de organización de documentos y control de páginas.

No debe posicionarse como:

* lector PDF
* editor PDF completo
* escáner de documentos
* herramienta OCR
* convertidor de formatos
* compresor de archivos
* reparador de PDF
* desbloqueador de contraseñas
* herramienta de firma electrónica
* servicio en la nube
* organizador mediante IA
* gestor documental empresarial
* garantía de compatibilidad o preservación perfecta para todos los PDF

La primera prueba visual debe comunicar inmediatamente:

**varios PDF → un PDF**

y/o:

**un PDF → varios PDF por páginas**

No debe abrir con:

* selector de archivos sin contexto
* ajustes
* My PDFs vacío
* editor de portada
* pantalla de monetización
* advertencias técnicas
* árbol de objetos PDF
* lista de páginas sin explicar los archivos resultantes
* privacidad sin mostrar primero la función
* archivos genéricos que no parecen documentos PDF

La confianza técnica debe expresarse con precisión: el contenido se procesa localmente, pero una reescritura puede afectar firmas digitales, formularios, marcadores complejos, etiquetas de página o destinos internos. Estas limitaciones no deben convertirse en el hook comercial, pero tampoco deben contradecirse mediante promesas absolutas.

# Default Screenshot Strategy

La recomendación global es un set de **6 screenshots**:

1. Unir o dividir PDF
2. Ordenar antes de unir
3. Dividir usando marcadores o puntos elegidos
4. Dividir en partes equilibradas o por máximo de páginas
5. Revisar y preparar el resultado
6. Guardar, abrir, compartir y encontrar los resultados

Puede utilizarse un set compacto de **5 screenshots** cuando la región responda mejor a mensajes breves y los métodos de split puedan combinarse sin perder claridad.

El set de 5 recomendado es:

1. Unir o dividir PDF
2. Ordenar antes de unir
3. Dividir por páginas a tu manera
4. Revisar y preparar el resultado
5. Guardar, abrir y compartir localmente

Un set de 7 screenshots sólo se justifica cuando marcadores, puntos manuales y distribución por páginas necesitan demostraciones separadas y cada asset aporta una motivación distinta.

La portada no recibe automáticamente una captura propia. Puede integrarse en la preparación del resultado o eliminarse del set cuando no sea una motivación relevante para la región.

Preferred language:

* Merge PDF files
* Combine documents in your order
* Split PDF by pages
* Use existing bookmarks
* Choose split points
* Set maximum pages per file
* Save new PDF files

Use “merge” for search recognition and “combine” when explaining the practical result. “Extract pages” may support specific split use cases but should not replace the broader split promise.

Primary value:

**Flexible document control without desktop complexity.**

# Palette Usage Rules

## Background Base

Used for:

* main canvas
* headline safe area
* large negative-space zones
* outer screenshot composition

The headline area must remain dark and visually stable.

---

## Background Secondary

Used for:

* phone shadows
* document cards
* soft gradients
* layered PDF sheets
* subtle separation between merge and split zones
* depth behind the device mockup

It must not create a bright panel behind the title.

---

## Merge Accent

Used for:

* source order
* convergence paths
* selected merge controls
* final merged PDF
* primary CTA highlights
* one-result success state
* selected cover page when shown

---

## Split Accent

Used for:

* split points
* branching connectors
* part numbers
* page ranges
* bookmark indicators
* selected split method
* generated PDF list
* maximum-page indicators

Merge and split must remain part of the same visual system.

They must not look like separate applications.

---

## Texture

Allowed:

* subtle matte grain
* low-contrast geometric depth
* extremely soft vignette
* minimal paper texture below approximately 3% visual intensity

Avoid:

* code
* PDF object trees
* dense file grids
* scanner textures
* visible document text behind the headline
* official seals
* signatures
* glow
* neon
* strong gradients
* random particles

# Output Presentation Rules

## Merge Results

Must show:

* several source PDF files
* visible source order
* one final filename
* one result
* a readable page-count summary when useful
* clear Save/Open/Share actions when present

Avoid:

* multiple final PDFs
* a result visually identical to one source without explanation
* a result that looks like a ZIP archive
* cloud-upload states
* claims that all interactive PDF behavior is preserved perfectly

---

## Split Results

Must show:

* one source PDF
* the selected split method
* a compact list of generated PDFs
* clear part numbers or page ranges
* the correct number of results
* one optional primary preview rather than repeated large thumbnails

Avoid:

* excessively long result lists
* missing, overlapping, or repeated page ranges
* implying deleted pages when the app creates separate results
* exact equality in MB
* maximum file size claims when the setting is maximum pages
* separate output covers that imply automatic design generation

---

# Example Content Strategy

Each region should use:

* fictional reports, annexes, course material, manuals, receipts, or administrative packets
* document types that feel familiar in the region without reproducing official forms
* generic filenames when a realistic example could expose personal information
* coherent source files for merge examples
* mathematically consistent page ranges for split examples
* neutral cover or title pages created specifically for the assets

Do not:

* use real personal data
* show real signatures, account numbers, addresses, IDs, QR codes, barcodes, or case numbers
* copy government forms or imply official approval
* use company-confidential documents
* show copyrighted reports or textbooks without permission
* imply that PMAS provides document templates
* reuse the exact same document examples in every region
* show paper being scanned when scanning is not a function

Exact filenames and document examples should be selected during asset production.

# Global Recommended Direction

## Strongest Global Promise

**Merge multiple PDFs into one document or split one PDF by pages your way.**

## Strongest Practical Promise

**Organize related PDF documents into one file, or divide a long PDF into useful page ranges using bookmarks, chosen split points, balanced parts, or a maximum number of pages.**

## Strongest Merge Proof

**Several PDFs in a user-selected order → one complete PDF result.**

## Strongest Split Proof

**One PDF with a selected method → several clearly labeled page-range files.**

## Strongest Differentiator

**Four ways to divide a PDF without turning the experience into a technical desktop workflow.**

## Strongest Trust Proof

**Your PDF content is processed on your device. No account. No document uploads for merging or splitting.**

## Strongest Conversion Logic

**Choose merge or split → control the document or page order → preview the output → prepare the result → save new PDF files locally.**

## Strongest Technical Guardrail

**PMAS creates new PDFs while preserving ordinary visible page content, but it must not promise perfect reconstruction of digital signatures, interactive forms, complex bookmarks, page labels, internal destinations, or every advanced PDF action.**
