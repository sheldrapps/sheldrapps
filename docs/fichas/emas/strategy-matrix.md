# EPUB Merge & Split — Strategy Matrix

## Purpose

Definir la estrategia regional de conversión para EPUB Merge & Split en todos los locales compatibles de Play Store.

Esta matriz guía:

* fichas localizadas de Play Store
* nombres y descripciones ASO
* feature graphics
* orden y cantidad de screenshots
* dirección visual
* selección de paletas
* ejemplos regionales
* conversion audits
* generación masiva de assets
* QA de promesas técnicas

La verdad del producto debe mantenerse en todos los locales:

**EPUB Merge & Split permite unir varios EPUB en un solo libro o dividir un EPUB en nuevos archivos usando capítulos, secciones, partes iguales, puntos personalizados o un tamaño máximo.**

La aplicación también permite, como parte del flujo:

* ordenar los EPUB antes de unirlos
* elegir y ajustar la portada del resultado
* revisar cómo quedará distribuido el contenido
* guardar los EPUB creados
* abrirlos con aplicaciones compatibles
* compartirlos
* encontrarlos nuevamente en My EPUBs
* procesar el contenido localmente en el dispositivo
* cambiar idioma y tema
* quitar anuncios mediante una opción de mejora

La estrategia regional debe adaptar la prioridad, el tono y la narrativa según lo que más favorezca la conversión en cada mercado.

No debe limitarse a traducir una ficha global.

---

# Global Strategy

El recorrido global recomendado es:

**elegir unir o dividir → organizar el contenido → revisar el resultado → preparar la portada → crear nuevos EPUB → mantener el control local**

La aplicación debe percibirse como una herramienta de organización EPUB flexible y especializada.

No debe posicionarse como:

* lector EPUB
* editor EPUB completo
* tienda de ebooks
* aplicación para descargar libros
* convertidor de formatos
* compresor de archivos
* reparador de EPUB
* herramienta DRM
* servicio en la nube
* organizador mediante IA
* herramienta oficial de Kindle, Kobo, Apple Books o Google Play Books
* garantía de compatibilidad con todos los EPUB o lectores

La primera prueba visual debe comunicar inmediatamente:

**varios EPUB → un EPUB**

y/o:

**un EPUB → varios EPUB**

No debe abrir con:

* selector de archivos sin contexto
* ajustes
* My EPUBs vacío
* editor de portada
* pantalla de monetización
* estructura técnica del EPUB
* lista de capítulos sin explicar el resultado
* privacidad sin mostrar primero la función
* archivos genéricos que no parecen EPUB

---

# Default Screenshot Strategy

La recomendación global es un set de **6 screenshots**:

1. Unir o dividir EPUB
2. Ordenar antes de unir
3. Dividir por capítulos o secciones
4. Dividir por partes, puntos personalizados o tamaño máximo
5. Elegir y ajustar la portada
6. Guardar, abrir, compartir y encontrar los resultados

Puede utilizarse un set compacto de **5 screenshots** cuando la región responda mejor a mensajes breves y los métodos de split puedan combinarse sin perder claridad.

El set de 5 recomendado es:

1. Unir o dividir EPUB
2. Ordenar antes de unir
3. Dividir a tu manera
4. Elegir la portada
5. Guardar, abrir y compartir localmente

Un set de 7 screenshots solo se justifica cuando capítulos, secciones y métodos avanzados necesitan demostraciones separadas y cada asset aporta un motivo de conversión distinto.

# Palette Usage Rules

## Background Base

Used for:

* main canvas
* headline safe area
* large negative-space zones
* outer screenshot composition

The headline area must remain dark and visually stable.

---

## Background Secondary

Used for:

* phone shadows
* cards
* soft gradients
* layered EPUB elements
* subtle separation between merge and split zones
* depth behind the device mockup

It must not create a bright panel behind the title.

---

## Merge Accent

Used for:

* source order
* convergence paths
* selected merge controls
* final merged EPUB
* primary CTA highlights
* selected result cover
* one-result success state

---

## Split Accent

Used for:

* split points
* branching connectors
* part numbers
* chapter ranges
* selected split method
* generated EPUB list
* maximum-size or custom-point indicators

Merge and split should remain part of the same visual system.

They must not look like separate applications.

---

## Texture

Allowed:

* subtle matte grain
* low-contrast geometric depth
* extremely soft vignette
* minimal book-page texture below approximately 3% visual intensity

Avoid:

* code
* XML
* file trees
* ZIP patterns
* dense grids
* book text
* visible pages behind the headline
* glow
* neon
* strong gradients
* random particles

# Output Presentation Rules

## Merge Results

Must show:

* several source EPUBs
* visible source order
* one final cover
* one final filename
* one result
* clear Save/Open/Share actions when present

Avoid:

* multiple final EPUBs
* repeated covers
* a result that looks like a ZIP archive
* an output visually identical to one source without explanation

---

## Split Results

Must show:

* one source EPUB
* selected split method
* one primary cover thumbnail
* a compact bullet list of generated EPUBs
* clear part numbers or chapter ranges
* the correct number of results

Avoid:

* repeating a large cover for every result
* excessively long result lists
* missing or repeated chapter ranges
* implying that the app created unrelated books
* exact byte equality unless verified

---

# Example Content Strategy

Each region should use:

* popular works without copyright restrictions in that region
* public-domain works with locally relevant recognition
* generic fictional examples when legal status is uncertain
* coherent titles for merge examples
* consistent chapter ranges for split examples

Do not:

* use the same books in every region by default
* use active-copyright translations
* reproduce modern commercial covers
* show publisher logos
* imply that EMAS provides or distributes the books
* include contemporary bestsellers
* use recognizable branded-reader interfaces

Exact titles should be selected during asset production.

# Monetization Matrix

| Locale group               | Recommended handling                                                                                                         |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| en-US, es-MX, pt-BR, hi-IN | Mention rewarded-ad access transparently near the end of the long description when applicable. Remove Ads remains secondary. |
| de-DE, ja-JP               | Keep monetization factual, minimal, and late. Avoid promotional upgrade language.                                            |
| fr-FR, it-IT               | Present the ad-free option as product polish, not a central benefit.                                                         |
| ar-SA                      | Keep monetization out of hero assets and avoid crowding RTL compositions.                                                    |
| ko-KR, zh-CN, zh-TW        | Mention Remove Ads in settings or description only. Do not weaken the efficient utility positioning.                         |
| ru-RU                      | Be explicit when necessary, but avoid making free limitations the first impression.                                          |

Global rules:

* Do not dedicate an early screenshot to ads.
* Do not call the app completely offline if ads or billing may need internet.
* Do not promise unlimited free merges or splits.
* Do not describe a rewarded ad as a product benefit.
* Do not show a fallback unless it exists.

# Regional Differentiation Rules

Localization is not translation.

Each locale must decide:

* whether merge or split should receive greater prominence
* whether “chapter” or “large file” is the stronger split motivation
* whether privacy is a primary proof or supporting proof
* whether technical precision or simplicity converts better
* which public-domain works feel locally familiar
* which localized verbs sound natural
* how much copy can fit without reducing readability
* whether 5 or 6 screenshots is stronger
* whether the cover deserves a dedicated screenshot
* whether maximum-size splitting should appear early

Every locale must preserve:

* both main functions
* source-to-result clarity
* user-controlled merge order
* the five real split methods
* accurate “equal parts” wording
* accurate maximum-size wording
* creation of new EPUB files
* local processing truth
* no-account and no-upload proof
* original/source continuity
* monetization as secondary
* absence of DRM and format-conversion claims

---

# Final Quality Bar

A locale strategy is approved only if:

* the first visual clearly communicates merge or split
* the hero includes EPUB or unmistakable EPUB visuals
* merge and split are visually distinguishable
* source and result files are distinguishable
* merge produces one visible result
* split produces several visible results
* merge order is proven
* chapter and section splitting are understandable
* advanced split methods are explained without crowding
* equal parts does not imply identical bytes
* maximum size does not look like compression
* custom points do not look like text editing
* cover selection remains connected to the final EPUB
* Save/Open/Share reflect real actions
* My EPUBs does not look like a reader or store
* local processing proof is present
* monetization remains secondary
* palette instructions are explicit
* Arabic assets are RTL-safe
* examples respect regional copyright
* no unsupported claims are introduced
* the regional angle differs for a real conversion reason
* the listing does not become a literal translation of en-US

# Global Recommended Direction

## Strongest Global Promise

**Merge multiple EPUBs into one book or split one EPUB your way.**

## Strongest Practical Promise

**Organize related EPUBs into one volume or divide a large EPUB into useful files using chapters, sections, equal parts, custom points, or a maximum size.**

## Strongest Merge Proof

**Several EPUBs in a user-selected order → one complete EPUB result.**

## Strongest Split Proof

**One EPUB with a selected method → several clearly labeled EPUB files.**

## Strongest Differentiator

**Five ways to divide an EPUB without turning the experience into a technical workflow.**

## Strongest Trust Proof

**Your EPUB content is processed on your device. No account. No book uploads.**

## Strongest Conversion Logic

**Choose merge or split → control the organization → preview the output → prepare the result → save new EPUB files locally.**
