# EPUB Merge & Split — Conversion Audit

## Purpose

Audit the conversion readiness, product accuracy, regional positioning, merge and split clarity, output-control proof, privacy messaging, monetization transparency, and unsupported-claim risk of every localized Play Store listing for EPUB Merge & Split.

This audit verifies that every locale preserves the real product promise while adapting its conversion angle to what users in that region are most likely to value.

The shared product foundation is:

**Merge multiple EPUB files into one organized book, or divide one EPUB into new files using chapters, sections, equal parts, custom split points, or a maximum file size.**

Users can also:

* Reorder EPUBs before merging
* Choose and adjust the result cover
* Review how content will be distributed
* Save created EPUB files
* Open results in compatible apps
* Share created files
* Find saved results in My EPUBs
* Process EPUB content locally on the device

The localized listings must not be literal translations of one global golden.

Each locale may change:

* the leading conversion angle
* the priority between merge and split
* the order of screenshots
* the number of screenshots
* the amount of technical explanation
* the vocabulary used for books, parts, chapters, and files
* the relative emphasis on privacy, control, simplicity, speed, or precision

Regional adaptation must not change the actual product scope.

---

## Global Product Identity

All locales must preserve the same product identity:

**EPUB Merge & Split is a local EPUB organization utility that creates new EPUB files by combining or dividing compatible source EPUBs.**

It is not:

* an EPUB reader
* a full EPUB editor
* a book-writing app
* an ebook downloader
* an ebook marketplace
* a general file compressor
* a universal format converter
* a DRM removal tool
* a cloud processing service
* an AI content-generation tool
* an automatic translation tool
* a metadata editor unless that capability is separately verified
* a guarantee of compatibility with every EPUB or reading application

The listing should sell control over EPUB organization, not abstract file manipulation.

---

## Global Conversion Standard

Every locale must communicate the following product truths, although the order and emphasis may vary by region:

1. The app works specifically with EPUB files.
2. Users can merge multiple EPUBs into one result.
3. Users can control the order before merging.
4. Users can split one EPUB using several methods.
5. Chapter and section splitting uses structure found inside the source EPUB.
6. Equal, custom, and maximum-size methods provide additional control.
7. The app creates new EPUB result files.
8. The user can choose or adjust the result cover where supported.
9. Created files can be saved, opened, and shared.
10. Source EPUBs are not presented as being destructively overwritten.
11. EPUB processing happens locally on the device.
12. No account is needed for EPUB processing.
13. EPUB content is not uploaded for merging or splitting.
14. Monetization remains secondary to the main utility.
15. No unsupported compatibility, DRM, editing, compression, or file-size guarantees are introduced.

The first visual impact should communicate one of these high-value relationships:

**Several EPUBs → one organized EPUB**

or:

**One EPUB → several useful EPUB parts**

or, preferably when regional conversion permits:

**Merge or split EPUBs according to your needs**

The listing must not open with:

* settings
* an empty My EPUBs page
* a file picker without context
* a technical EPUB structure screen
* an advertisement or upgrade screen
* a generic privacy statement without showing the core product
* a chapter list that does not explain the output
* a cover editor without explaining that it belongs to a merge or split result
* an abstract file-management composition

## Default Screenshot Strategy

The default global recommendation is a compact set of **6 screenshots**:

1. Main merge-or-split promise
2. Merge ordering and organization
3. Split by chapters or sections
4. Equal parts, custom points, or maximum size
5. Result cover and final preparation
6. Created files, local storage, opening, sharing, and privacy

This is a default conversion structure, not a rigid localization rule.

A regional golden may use **5 screenshots** when:

* chapter/section and advanced splitting can be combined clearly
* copy length requires fewer, stronger compositions
* one function has significantly higher regional search intent
* the market responds better to a shorter product story
* the available raw UI allows two related benefits to be shown without crowding

A regional golden may use **7 screenshots** only when:

* each additional screenshot communicates a genuinely distinct conversion benefit
* merge and split require separate proof
* the locale benefits from additional explanation
* the extra screenshot is not settings, monetization, or generic product completeness
* the sequence remains understandable at Play Store preview size

Do not add screenshots only to show every screen in the application.

## Core Conversion Hierarchy

The default hierarchy is:

**Main promise → organization control → structural splitting → advanced splitting → result identity → local ownership**

Regional variants may legitimately prioritize different paths.

Examples:

### Merge-first hierarchy

Useful when searches around combining books, volumes, collections, or serialized works are more valuable:

**Several books → order control → one result → selected cover → save and share**

### Split-first hierarchy

Useful when large-file management, chapter extraction, or device limitations are stronger motivations:

**Large EPUB → choose split method → preview parts → save smaller EPUBs → local control**

### Privacy-first supporting hierarchy

Useful in markets where file-upload distrust is an important conversion factor:

**Merge or split locally → no book uploads → control the result → save and share**

Privacy may strengthen the primary proposition, but it should not replace it.

## Merge-Scope Accuracy

Safe merge claims:

* Merge multiple EPUBs into one book
* Combine EPUB files in the order you choose
* Organize EPUBs before creating the result
* Select the cover for the merged EPUB
* Create one new EPUB from several source files
* Keep source EPUBs available separately
* Save, open, or share the merged result

Use carefully:

* Unlimited EPUBs
* Merge any number of EPUBs
* Preserve every style and format
* Combine all navigation structures
* Merge every EPUB version
* Maintain perfect compatibility
* Preserve every metadata field

These claims require verification against:

* memory handling
* practical device limits
* EPUB 2 and EPUB 3 handling
* navigation and TOC generation
* metadata strategy
* duplicate resource handling
* internal identifier rewriting
* stylesheet and font collisions
* malformed source EPUB behavior
* output validation

Avoid:

* Merge any ebook format
* Merge Kindle books
* Merge DRM-protected books
* Combine PDF, MOBI, AZW, or CBZ files
* Join ZIP files into EPUB
* Preserve every book exactly
* Guaranteed compatibility with every reader
* Automatic editorial correction
* Rewrite or improve book content

## Split-Scope Accuracy

Safe split claims:

* Split an EPUB by chapters
* Split an EPUB by sections
* Divide an EPUB into a selected number of parts
* Choose custom split points
* Create EPUB parts below or around a selected maximum size, according to the implemented behavior
* Review which chapters or sections will be included
* Create several new EPUB files
* Preserve the original EPUB separately

Use carefully:

* Equal parts
* Same-size parts
* Exact maximum file size
* Perfect chapter detection
* Extract every chapter
* Split every EPUB
* Preserve all internal navigation
* Create independent books from every section

“Equal parts” must reflect the actual algorithm.

It may mean:

* a similar number of content documents
* a similar number of chapters
* a similar calculated content weight
* another verified distribution method

It must not automatically be interpreted as identical byte size.

“Maximum size” must also reflect the implementation.

Safer wording includes:

* Split using a selected maximum size
* Keep generated files within the selected size when possible
* Create smaller EPUB parts based on a size limit
* Divide the book according to the selected file-size setting

Avoid guaranteeing an exact resulting byte size unless the engine enforces and validates it.

## Chapter and Section Detection Accuracy

Chapter and section splitting depends on the structure available in the source EPUB.

The listing may explain this using accessible language:

* Uses the chapters found in your EPUB
* Splits according to the book structure
* Uses available chapters or sections
* Preview how the book will be divided
* Choose between detected chapters and broader sections

Avoid implying that:

* all EPUBs contain reliable chapter information
* every heading becomes a chapter
* chapter names are always present
* sections are semantically interpreted using AI
* the app understands the literary meaning of the content
* the app reconstructs missing chapters
* chapter detection works identically in every EPUB

Technical terms such as spine, navigation document, NCX, or OPF should not dominate public conversion copy.

They may appear only where a technical regional audience benefits and the statements are accurate.

## Cover-Workflow Accuracy

Safe claims:

* Choose the cover for the result
* Select a cover from the available EPUBs
* Adjust the result cover
* Preview the selected cover
* Give the merged EPUB a recognizable cover
* Prepare the cover before saving

Validate before claiming:

* Every split part can use a different cover
* Covers are generated automatically
* Cover text is generated
* The app redesigns covers
* Original covers are enhanced
* The cover is optimized for every device
* The app supports every image format
* The cover editor contains the full functionality of another app

The cover workflow must be positioned as preparation of the EPUB result.

It must not make EMAS look like:

* a complete graphic-design app
* EPUB Cover Changer
* Cover Creator for Kindle
* an AI cover generator
* a generic photo editor

## Output and File-Control Accuracy

Every locale should make the output understandable.

For merge:

**Several source EPUBs → one created EPUB**

For split:

**One source EPUB → several created EPUB files**

The listing should make clear that the app produces new files.

Safe claims:

* Save created EPUBs
* Open the result in compatible apps
* Share created EPUB files
* Find results in My EPUBs
* Keep the source EPUB separately
* Create a new EPUB result

Avoid:

* Open in every ebook reader
* Perfect compatibility with Kindle or Kobo
* Automatically upload to reading platforms
* Sync across devices
* Publish the result
* Send directly to an ebook store
* Replace the original EPUB unless that is explicit behavior
* Back up files to the cloud

“Open” must mean using the system or a compatible installed application, not reading the EPUB inside EMAS unless an internal reader actually exists.

---

## Privacy and Local-Processing Accuracy

Approved high-level trust proof:

* EPUB processing happens on your device
* No account is required
* No book uploads are needed
* Your EPUB content stays under your control
* Files are created locally
* Merge and split processing stays on the device

Avoid:

* 100% offline, if rewarded advertisements or access checks may require internet
* Nothing ever connects to the internet
* No network access
* Completely offline in every mode
* Anonymous cloud processing
* Secure temporary uploads
* Encrypted server conversion

The most accurate default statement is:

**Your EPUB content is processed on your device and is not uploaded for merging or splitting.**

This distinguishes file processing from advertising, billing, analytics, or other app services.

---

## Monetization Accuracy

Monetization must remain secondary.

Approved phrasing when applicable:

* Remove ads with an upgrade option
* Some free creation actions may use a rewarded ad
* Upgrade for an ad-free experience
* If an ad cannot load, the app provides the implemented fallback
* The result workflow remains clear if advertising is unavailable

Avoid:

* Free unlimited merges
* Free unlimited splits
* Always free
* No ads
* Completely offline
* Unlimited processing
* Lifetime access to every future premium feature
* Pro output unless a specific premium output difference exists
* Hiding a required advertisement from the listing when it materially affects the main workflow

The first screenshots must not focus on monetization.

Settings and Remove Ads should not replace proof of merge, split, or output control.

---

## Unsupported Claim Risk

No locale may introduce claims about:

* Removing DRM
* Processing DRM-protected ebooks
* Bypassing ebook protections
* Downloading books
* Providing free ebooks
* Editing the complete text of the EPUB
* Translating EPUB content
* Correcting grammar or spelling
* Rewriting chapters
* Generating chapters or summaries
* Converting PDF, MOBI, AZW, CBR, CBZ, DOCX, or other formats
* Compressing EPUBs unless a separate verified compression function exists
* Reducing file size through image optimization unless verified
* Repairing damaged EPUBs unless a repair flow is part of EMAS
* Recovering missing content
* Guaranteeing exact equal sizes
* Guaranteeing exact maximum file size
* Guaranteeing compatibility with all readers
* Uploading directly to Kindle, Kobo, Apple Books, Google Play Books, or another service
* Official affiliation with an ebook store or reading platform
* AI-based chapter detection
* Cloud processing
* Automatic publishing
* Unlimited source files unless verified
* Unlimited output size unless verified

Unsupported claim risk must score **5/5** before publication.

# Global Findings

All localized variants must preserve the same actual product identity:

**EPUB Merge & Split combines compatible EPUB files into one organized result and divides compatible EPUBs into new files using several user-controlled methods.**

The strongest default conversion hierarchy is:

**Merge or split → control the organization → preview the result → choose the cover → save new EPUB files → keep processing local.**

The strongest merge proof is:

**Multiple EPUBs shown in a user-selected order, producing one clear result.**

The strongest split proof is:

**One EPUB shown with a selected method and an understandable preview of the resulting parts.**

The strongest differentiation proof is:

**Chapters and sections for natural structure, plus equal parts, custom points, and maximum size for additional control.**

The strongest output proof is:

**Created EPUB files can be saved, opened with compatible apps, shared, and found again in My EPUBs.**

The strongest trust proof is:

**EPUB processing happens on the device. No account is required. EPUB content is not uploaded for merging or splitting.**

The largest global conversion risk is making EMAS look like:

* a generic file manager
* a file compressor
* a universal ebook converter
* a full EPUB editor
* an ebook reader
* a cloud processing service
* an AI organization tool
* a DRM utility
* a collection of unrelated EPUB tools

The largest technical-accuracy risks are:

* promising exact equal file sizes
* promising exact maximum-size outputs
* promising universal chapter detection
* promising unlimited input files without practical validation
* promising full style and navigation preservation without validation
* implying that every EPUB can be merged or split successfully

# Final Conclusion

A localized EPUB Merge & Split listing is approved when it:

* communicates the merge and split value immediately
* adapts its conversion angle to the target region
* proves user control over ordering and split methods
* shows understandable source-to-result relationships
* presents the cover as result preparation
* shows new EPUB files as the final output
* supports local-processing trust without replacing the main value
* treats monetization as secondary
* avoids claims outside the real implementation

The default global conversion path is:

**Choose merge or split → organize the content → preview the output → prepare the result → save new EPUB files locally.**

The exact order may change by region.

The regional audit must ask:

**What does this market value most: simplicity, precision, privacy, large-file handling, organization, speed, or flexible control?**

The localized golden should then lead with that value while preserving the same real product scope.
