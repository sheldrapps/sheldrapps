# EPUB Merge & Split — Creative Brief

## Purpose

Definir la estrategia creativa, comercial, visual, regional y de conversión para las fichas de Play Store de EPUB Merge & Split.

Este documento debe guiar:

* generación de fichas de Play Store
* golden listings
* descripciones ASO
* feature graphics
* estrategia de screenshots
* localización regional
* strategy matrix
* conversion audit
* generación masiva de fichas
* selección de ejemplos visuales
* control de promesas técnicas
* QA de assets

Este documento funciona como fuente estratégica principal para EMAS.

Todas las fichas, golden listings, strategy matrices, conversion audits e instrucciones visuales deben respetar este brief.

La aplicación no debe explicarse como una colección de pantallas internas. La ficha debe vender el resultado práctico:

**varios EPUB organizados en un solo libro, o un EPUB dividido en archivos nuevos según las necesidades del usuario.**

El recorrido principal debe sentirse así:

**elige unir o dividir → organiza el contenido → revisa cómo quedará → prepara el resultado → guarda nuevos EPUB en tu dispositivo.**

# Split Strategy

## Main Split Value

El usuario puede elegir cómo dividir el EPUB según su objetivo.

No todos los usuarios buscan lo mismo:

* algunos quieren un EPUB por capítulo
* otros quieren agrupar varios capítulos
* otros necesitan una cantidad concreta de partes
* otros necesitan controlar exactamente dónde comienza una nueva parte
* otros necesitan archivos más pequeños

La ficha debe explicar esta flexibilidad sin convertir la experiencia en una lista técnica abrumadora.

---

## Split Methods

### Chapters

Utiliza los capítulos detectados en el EPUB como límites de división.

Puede producir:

* un EPUB por capítulo
* grupos de capítulos, dependiendo del flujo seleccionado
* una preview de qué capítulos tendrá cada resultado

La ficha no debe prometer que todos los EPUB contienen capítulos correctamente definidos.

---

### Sections

Utiliza agrupaciones o secciones identificadas en la estructura del EPUB.

Debe diferenciarse visual y verbalmente de capítulos.

No debe utilizarse “sección” como un simple sinónimo de capítulo si la implementación mantiene una diferencia real.

---

### Equal Parts

Divide el contenido en una cantidad seleccionada de partes.

Debe especificarse internamente qué significa “iguales”:

* cantidad similar de capítulos
* cantidad similar de documentos
* peso aproximado de contenido
* otra métrica implementada

La comunicación pública no debe afirmar que los archivos tendrán exactamente el mismo número de bytes.

---

### Custom Split Points

Permite seleccionar puntos concretos donde comenzará un nuevo EPUB.

La comunicación debe mostrar:

* límites válidos
* puntos entre capítulos o secciones
* preview del contenido de cada parte

No debe parecer edición del texto.

---

### Maximum Size

Utiliza un límite de tamaño como criterio para generar partes más pequeñas.

La comunicación pública debe evitar:

* tamaño exacto garantizado
* compresión
* reducción de calidad
* optimización automática de imágenes

Preferir:

* Divide usando un tamaño máximo
* Crea archivos más pequeños
* Usa un límite de tamaño
* Separa el contenido según el tamaño elegido
* Mantén las partes dentro del límite cuando sea posible

---

# Cover Workflow Strategy

## Main Cover Value

La portada permite que el resultado sea fácil de reconocer.

En merge, la portada ayuda a convertir varios archivos en un libro final coherente.

En split, la portada mantiene una identidad visual consistente entre las partes.

---

## Safe Cover Claims

* Elige la portada del resultado
* Selecciona una portada disponible
* Ajusta cómo se verá
* Previsualiza la portada
* Identifica fácilmente el nuevo EPUB
* Prepara la portada antes de guardar

---

## Cover Guardrails

No afirmar:

* generación automática de portadas
* creación de portadas mediante IA
* portadas diferentes para cada parte
* mejora automática de calidad
* rediseño automático
* generación de títulos
* compatibilidad con cualquier formato de imagen
* herramientas equivalentes a una app completa de diseño

El flujo debe sentirse como preparación del resultado, no como el producto principal.

# Screenshot Philosophy

## First Screenshot Objective

Debe responder en un vistazo:

**“¿Esta app puede unir o dividir mis EPUB?”**

No debe requerir leer copy pequeño.

---

## First Screenshot Must Not Answer

* Qué ajustes tiene la app
* Cómo funciona internamente un EPUB
* Qué tamaño máximo puede configurarse
* Qué portada puede elegirse
* Qué archivos hay en My EPUBs
* Cómo se quitan los anuncios

---

## Default Screenshot Strategy

El set global recomendado es de **6 screenshots**:

1. Promesa principal: unir o dividir EPUB
2. Ordenar EPUB antes de unir
3. Dividir por capítulos o secciones
4. Dividir por partes, puntos o tamaño
5. Elegir y ajustar la portada
6. Guardar, abrir, compartir y mantener los archivos locales

Este orden no es obligatorio para todas las regiones.

Cada ficha regional puede modificarlo si existe una razón clara de conversión.

---

## Compact Five-Screenshot Strategy

Puede utilizarse un set de 5 cuando capítulos, secciones y métodos avanzados pueden combinarse sin perder claridad:

1. Une o divide EPUB
2. Ordena antes de unir
3. Divide a tu manera
4. Elige la portada del resultado
5. Guarda, abre y comparte localmente

No se deben combinar métodos si la captura termina saturada o deja de explicar qué resultado produce cada opción.

---

## Expanded Seven-Screenshot Strategy

Solo debe utilizarse cuando cada captura adicional aporte una motivación distinta:

1. Promesa general
2. Merge
